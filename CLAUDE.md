# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OxideSwarm is a zero-broker distributed compute grid in Rust (edition 2021, MSRV 1.75): a **Master** coordinator dispatches tasks to **Workers** (macOS, Windows, Linux, Android) over length-delimited TCP or iroh QUIC/P2P (NAT traversal). A separate **Agent Mesh** (WebSocket relay hub for coding agents) can submit work into the grid through an in-process bridge. All documentation and launchers are maintained in clean, open-source English; `PROJECT.md` holds the layer breakdown and design rationale.

## Commands

The Cargo workspace has no root package, and **package names differ from directory names**:

| Directory | Package (`-p`) | Notes |
|---|---|---|
| `crates/core` | `rusty_grid_core` | wire protocol, tasks, capabilities, discovery, workflow modes, `cluster_auth` (secret handshake) |
| `crates/master` | `rusty_grid_master` | features `p2p`, `dashboard` (both default) |
| `crates/worker` | `rusty_grid_worker` | features `p2p` (default), `gpu-wgpu` (opt-in; `rusty_grid_cli` forwards it: `cargo build --release --bin oxideswarm --features gpu-wgpu` is the GPU-capable worker) |
| `crates/cli` | `rusty_grid_cli` | bins `oxideswarm`, `rusty-grid` (identical alias), `ox-mode`; modules `connect` (client plumbing), `secret_cmd` (secrets) |
| `crates/android_bridge` | `rusty_grid_android_bridge` | cdylib `liboxideworker.so` + rlib |
| `crates/agent_mesh` | `agent_mesh` | bin `agent-mesh` |

```bash
cargo build --bin rusty-grid                      # what test_integration.sh and most scripts expect (target/debug/rusty-grid)
cargo check --workspace --all-targets             # plan treats 0 warnings as the bar
cargo test --workspace                            # full suite (many stress tests; slow)
cargo test --workspace --lib                      # quick unit tests only (`ox-mode test quick`)
cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all -- --check   # = `ox-mode test lint`

# single integration test (target name = [[test]] name, package = owning crate)
cargo test -p rusty_grid_master --test m4_scheduling
cargo test -p rusty_grid_master --test m4_scheduling -- some_test_name --nocapture
cargo test -p rusty_grid_core --lib protocol::          # unit tests in one module

cargo test -p rusty_grid_worker --features gpu-wgpu     # real wgpu path (Metal/Vulkan/DX12); a host without a GPU skips those tests, RUSTY_GRID_REQUIRE_GPU=1 makes that a failure
cargo run --release -p rusty_grid_worker --features gpu-wgpu --example gemm_bench -- 1024   # GPU vs CPU timing + the adapter in use
cargo check -p rusty_grid_master --no-default-features  # must keep compiling without dashboard/p2p

cargo mode <test|dev|doc|research> [action]       # alias in .cargo/config.toml -> ox-mode (also `cargo xtask`); ./ox-mode is a symlink to scripts/mode.sh
./test_integration.sh                              # E2E: 1 master + 3 workers (one simulated GPU), loopback, private HOME, ephemeral ports
./run_chaos_test.sh                                # starts its own cluster, SIGKILLs a worker that holds running tasks, asserts re-execution (fails otherwise)
./run_cluster_benchmark.sh                         # two-node benchmark: two local workers (default) or a phone via --adb-id
python tests/run_all_mesh_tests.py                 # Agent Mesh protocol suites against a PYTHON reference hub (not the Rust hub); tests/test_challenger_*.py individually
python3 tests/test_launcher_scripts.py             # launcher/installer scripts vs fake binaries in a private HOME (stdlib only; OX_SCRIPT_ROOT=<old checkout> for a mutation check)
```

Run a local cluster by hand (loopback: no cluster secret needed):

```bash
./target/debug/rusty-grid master                        # = --listen 127.0.0.1:8088, dashboard 127.0.0.1:8080
./target/debug/rusty-grid worker --simulate-gpu         # --master defaults to 127.0.0.1:8088
./target/debug/rusty-grid submit --command echo --wait -- hi   # add --gpu to require a GPU worker
```

`--command` takes an executable with trailing args after `--` (there is no `--require-gpu`; the flag is `--gpu`). To let other machines join,
listen on `0.0.0.0:8088`; the first start then creates `~/.oxideswarm/cluster.secret` (see Security model).

Ports: master cluster TCP **`:8088`** (the only valid `--master` target; workers and clients connect here), dashboard/REST/WS **`:8080`**
(HTTP, never a `--master` target; a worker also serves a small unauthenticated "standby portal" on 8080), UDP discovery beacon **`:8089`**,
`scripts/sync_network` probe `:8085`. The agent-mesh hub also defaults to `:8088` (loopback): use another port when it runs next to a master.

## Architecture

### Test layout (non-obvious)
Most integration tests live in the **root `tests/` directory**, but there is no root package, so they are not auto-discovered. Each one is registered in a crate's `Cargo.toml` as `[[test]] name = ... path = "../../tests/<file>.rs"` (the owning crate is the one whose API it exercises, e.g. `tests/m4_scheduling.rs` → `rusty_grid_master`). **A new file in `tests/` will silently never run until you add a `[[test]]` entry.** Crate-local tests in `crates/*/tests/` are auto-discovered. Test file names (`m3_challenger_1_stress`, etc.) are milestone/adversarial-review artifacts, not a meaningful taxonomy. Tests bind `127.0.0.1:0` and use port files for ephemeral ports; keep it that way.

### Layer 1 — the grid (`core`, `master`, `worker`, `cli`)
- **`core`** is the shared contract: `protocol.rs` (messages + codec), `task.rs` (`Task`, `TaskSpec`, `TaskResult`, `CheckpointData`), `capabilities.rs` (`WorkerCapabilities`, `MobileCapabilities`), `transport.rs` (`GridStream` = TCP | in-memory Duplex | iroh `BiStream`), `discovery.rs` (UDP beacon, MAC'd when a secret exists; the beacon's `web_ui_url` is empty when the dashboard is not reachable from the network, and the worker standby portal then shows its standby page instead of guessing `http://<master>:8080`), `cluster_auth.rs` (`ClusterSecret`, `client_handshake` / `server_handshake`), `mapreduce.rs`, `mode.rs` (the test/dev/doc/research workflow-mode engine behind `ox-mode`), `error.rs` (`GridError`, incl. `AuthRequired` / `AuthFailed`).
- **Wire protocol** (`core/src/protocol.rs`): 4-byte big-endian length prefix, max 64 MB frame, then a **1-byte format discriminator** (`0x02` bincode, `0x01` tagged JSON, `0x03` cluster-auth handshake frame, `0x04` AEAD encrypted; raw legacy JSON starting `{` / `0x7B` is also accepted on read). Each peer picks a `WireCodec`. Messages flow `WorkerMessage` (worker→master), `MasterMessage` (master→worker), `ClientMessage`/`ClientResponse` (CLI→master), multiplexed on the master's single listener via `InboundMessage`. Post-handshake TCP traffic on authenticated connections is encrypted via ChaCha20-Poly1305 (`0x04`) using directional HMAC keys derived from `cluster.secret`.
  - **Protocol version & capability negotiation:** the connection handshake formally exchanges `PROTOCOL_VERSION` and `ProtocolCapabilities` flags (with backwards compatibility for legacy unnegotiated endpoints), preventing bincode deserialization errors and dropping unknown variants while enabling graceful capability negotiation.
  - **Gotcha when adding/changing a message variant:** every public message enum has hand-written `Human*` (serde `tag = "type"` JSON) and `Binary*` (bincode-friendly) mirror enums plus `From` conversions and manual `Serialize`/`Deserialize` that dispatch on `is_human_readable()`. A new variant or field must be added to the public enum **and both mirrors and all four `From` impls**, or one codec will fail/diverge. `task::Bytes` is a newtype around `bytes::Bytes` for the same reason (zero-copy stdout/stderr/stdin).
- **P2P/QUIC** (feature `p2p`, default): iroh endpoint with ALPN `rusty-grid/v1`; each connection carries two bidirectional streams, `STREAM_CONTROL = 0x01` (heartbeats/control) and `STREAM_DATA = 0x02` (task payloads/results) so bulk data can't head-of-line-block heartbeats. The master's P2P identity is persisted in `~/.oxideswarm/master_key.bin` (stable ticket across reboots) unless `ephemeral_key`/`RUSTY_GRID_EPHEMERAL_KEY` is set.
- **`master`**: `server.rs` (`MasterServer` → `MasterHandle`; connection handling, handshake, failover) is the hub that wires together `registry.rs` (`WorkerRegistry`, worker status/telemetry), `queue.rs` (`TaskQueue` with an 8-state FSM `Submitted→Queued→Scheduled→Running→Completed/Failed/Retrying/Cancelled`, `can_transition_to` guards every move; retries with backoff; checkpoint retention; LRU/TTL eviction of terminal tasks), `scheduler.rs` (`WorkloadScheduler::matchmake` + micro-batched `schedule_batch`; strict GPU routing prioritizing idle hardware GPU `wgpu` workers over simulated GPU `--simulate-gpu` workers; host-CPU backpressure), `reaper.rs` (heartbeat timeout → requeue), `mapreduce.rs`, `auth.rs` (RBAC scopes via Bearer/`X-API-Key`/`?token=` for the **dashboard** only; `AuthConfig::default()` has `dev_mode` **off** — the loopback bypass needs `--dev` / `OXIDE_DEV_MODE=1|true`, and tests that want it use `AuthConfig::dev()`; see Security model). Worker disconnect triggers requeue, resuming from the last `CheckpointData` via `MasterMessage::AssignTaskWithCheckpoint`. Failover sweeps are per session and **a sweep of session `s` also takes every older session of that worker** (a handler aborted by a newer registration never sweeps; the next sweep heals it); the supersede sweep runs in its own spawned task for the same reason. `WorkloadScheduler::dispatch` reserves channel room first and then confirms under the queue lock that the task is still `Scheduled` on that session (`TaskQueue::deliver_if_scheduled`), so a task cancelled mid-pass is never assigned. In the placement engine a task that only waits for slots reserves the worker nearest to fitting it for the rest of the pass (`Engine::hold_back`), which is what keeps a wide task from being starved by a stream of narrow ones (the cost: that worker's free slots idle until it drains).
- **Dashboard** (feature `dashboard`): the live router is `web_ui.rs` (REST + `/ws` + SSE), which serves `crates/master/src/dashboard.html` via `include_str!` (no CDN/npm). `dashboard/mod.rs` + `dashboard/dto.rs` supply `DashboardState` and DTOs; `dashboard/index.html` is **not** the file that gets served. Server pushes updates over a `broadcast::Sender<DashboardStreamMessage>`.
- **`worker`**: `client.rs` (`WorkerClient`: connect/register/reconnect with `backoff.rs`, active-task table, concurrency semaphore), `heartbeat.rs` (load telemetry), `runner.rs` (`TaskRunner`: bounded stdout/stderr capture, timeouts, cancellation; exit-code mapping is a table in its module docs, `130` means cancelled and nothing else), `process_tree.rs` (every task process leads its own process group — `killpg` TERM, grace, KILL — or atomic Windows Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` created via `CREATE_SUSPENDED`, and Linux `PR_SET_PDEATHSIG` so worker termination cleans up all child processes; `ProcessPriority`, below-normal by default; `terminate_all_task_process_trees()` for signal handlers; task processes do not inherit `OXIDESWARM_SECRET[_FILE]` / `OXIDE_MESH_TOKEN`), `sandbox.rs` (per-task dirs, `sanitize_relative_path`, base-dir chain explicit > `RUSTY_GRID_SANDBOX_BASE_DIR` > `TMPDIR` > platform temp, checked at `run()` start), `gpu.rs` (what a worker may advertise: a real GPU only if the binary has the wgpu engine **and** an adapter started, `--gpu` on a build without it is refused with a startup notice; `check_gemm_request` limits, `GpuError`), `cpu_simd.rs` (the CPU GEMM behind the labelled `--simulate-gpu` test mode and the sampled `f64` oracle `verify_gemm` that every result must pass before `Status: VERIFIED_OK`) and `wgpu_engine.rs` + `shaders/gemm.wgsl` (feature `gpu-wgpu`: error scopes + device-lost callback + `catch_unwind` turn every wgpu failure into a failed `TaskResult`, `EngineProvider` rebuilds a lost engine, the compute runs under `spawn_blocking`; an already submitted dispatch cannot be interrupted). `shaders/hash.wgsl` is experimental and unused. A real-GPU worker never falls back to the CPU: the task fails with the reason.
- **`cli`**: `cli_app.rs` (clap: `master|worker|submit|status|workers|mapreduce|secret|mode`), `config.rs` (precedence **CLI flag > `RUSTY_GRID_*` env > config file (`--config`, `RUSTY_GRID_CONFIG`, `./rusty-grid.{toml,json}`, else `~/.oxideswarm/rusty-grid.toml`) > defaults**; exactly ONE config file is auto-loaded), `connect.rs` (default master address `127.0.0.1:8088`, `master_requires_secret`, and `connect_master`, the single authenticated connect helper every client command uses), `secret_cmd.rs` (secret resolution `--secret` > `--secret-file` > `OXIDESWARM_SECRET` > `OXIDESWARM_SECRET_FILE` > config `secret`/`secret_file` > `~/.oxideswarm/cluster.secret`, the `secret generate|show` subcommand, the master's secret policy), `mode_cli.rs`. `main.rs` (`oxideswarm`) and `bin/rusty_grid.rs` (`rusty-grid`) are the same `run_cli()`; `bin/ox_mode.rs` is the standalone workflow-mode runner. Env var prefix is still `RUSTY_GRID_*` (not `OXIDESWARM_*`). A worker keeps its id across restarts only when it is named (`~/.oxideswarm/worker_id.<name>`) or `RUSTY_GRID_WORKER_ID_FILE` is set (`worker::identity::persistence_wanted`): unnamed workers under one HOME would share an id and the master would keep superseding each other. `--web-ui-addr` cannot be combined with `--dashboard-port` (clap conflict) and outranks a `dashboard_port` from env/config.

### Layer 2 — Android (`android_bridge`, `packaging/android`)
`oxideworker` cdylib runs the worker and a master **in-process** on Tokio threads via JNI (the worker loop itself needs no child process; but `TaskRunner` still spawns children for command/shell/compile tasks, which the Phantom Process Killer can kill). The JNI bridge exports `nativeSetClusterSecret` and `nativeStartWorkerWithSecret` for cluster secret authentication. `WorkerClient::run` refuses to start (clear `GridError::Config`) when the task sandbox base dir is not writable, and on Android the default (`/data/local/tmp`) is not: the Kotlin service therefore calls `OxideWorkerBridge.setSandboxDir(<cacheDir>/sandboxes)` (JNI `nativeSetSandboxDir`, `set_sandbox_dir_impl`) before `nativeStartWorker`, and `start_worker_impl` checks the directory itself, returning `false` with `ERROR: <reason>` in the status instead of starting a thread that dies unseen. Process-global state lives in `OnceLock<Arc<WorkerState>>`, and the P2P endpoint must be closed from its own runtime thread on shutdown. Build with `packaging/android/build_android_jni.sh` (outputs into the Gradle app's `jniLibs/`); the Kotlin app is under `packaging/android/app/`. Details: `ANDROID_ARCHITECTURE.md`.

### Layer 3 — Agent Mesh (`agent_mesh`, `scripts/agent_node.py`, `packaging/agent_mesh`)
Independent of the grid wire protocol: an Axum WebSocket hub (`hub.rs`) routes `AgentMeshEnvelope`s (`protocol.rs`) point-to-point between nodes with ACK/NACK and SHA-256 payload verification; `client.rs` is the Rust node, `executor.rs` the command executor (timeouts, **not a sandbox**), `scripts/agent_node.py` a dependency-light Python equivalent. The hub requires a token off loopback (`hub.rs`: `HubConfig::auth_token`). `bridge.rs` (`AgentGridBridge`) is the convergence point: it holds a `MasterHandle` and turns `grid_compute|grid_compile|grid_submit|grid_status` envelopes into master `Task`s. `--grid-master <ADDR>` makes the hub start its own embedded master on ADDR (it does not connect to a running one) and route agent tasks to it; off loopback that master needs a cluster secret (`--secret` / `OXIDESWARM_SECRET`, else the default secret file) or `--insecure` (`main.rs`: `grid_master_secret`). When unconfigured, `grid_*` envelopes receive `ERR_BRIDGE_NOT_CONFIGURED`.

### Layer 4 — sync & benchmarks (`scripts/sync_network`, `benchmarks/interconnect`)
`sync_network` is a shared-folder role claim plus an HTTP `/ping` reachability probe on :8085 between two machines (Python/sh/cmd); it never starts or checks the grid, and it must never carry tickets or the cluster secret. `benchmarks/interconnect` holds a recorded one-off WAN comparison dataset and a validator script (it does not measure Tailscale/Cloudflare). Neither is part of the Cargo build.

## Security model (details: `docs/SECURITY.md`)
- **Cluster secret**: a master that is reachable beyond loopback (non-loopback `--listen`, or `--p2p`) must have one; `run_master` auto-generates `~/.oxideswarm/cluster.secret` (mode 600) on first start and prints a copy instruction, unless `--insecure`. Workers/clients refuse to talk to a remote, `auto`-discovered or P2P-ticket master without a secret unless `--insecure` (`master_requires_secret`, exit code 6 = auth failure). The handshake (`cluster_auth.rs`, format byte `0x03`) runs before the first `InboundMessage` on TCP **and** on iroh streams. Authenticated TCP post-handshake traffic is encrypted via ChaCha20-Poly1305 (`0x04`) using directional keys (`oxs1-aead-c2s` and `oxs1-aead-s2c`) derived from `cluster.secret` (unauthenticated loopback fallback uses `0x01`/`0x02` directly).
- **Library vs CLI**: only the CLI layer resolves secrets; `ServerConfig::with_cluster_secret` / `WorkerConfig::with_cluster_secret` take it explicitly, so tests that do not set one run unauthenticated on loopback.
- **Dashboard policy**: loopback-only unless `--web-ui-addr` names another interface; a bare loopback master has a usable local dashboard; the dev bypass (`--dev`, `OXIDE_DEV_MODE`) applies only to loopback peers with loopback `Host`/`Origin` and no `X-Forwarded-*`, and **never when the dashboard listener is bound to a non-loopback address**. When a secret exists the dashboard Admin token is `HMAC(secret, "oxs1-dashboard-admin")` (`oxideswarm secret show --dashboard-token`).
- **Agent mesh hub**: token (`--token` / `OXIDE_MESH_TOKEN`), loopback default, non-loopback needs a token or `--insecure`; `/api/nodes` and `/api/status` need the token, or (no token) a loopback `Host` header; it can make nodes run `shell_exec`, so never expose it to the Internet.
- **Task identity**: workers run tasks as their own OS user and pass their environment on; installers must not default to root/SYSTEM (macOS `UserName`, Windows `NT SERVICE\OxideSwarmWorker`).

## Conventions and pitfalls
- `.agents/`, `*.log`, `ticket.txt`, `*.port`, and `tests/*_results.json` are gitignored scratch output from prior agent runs — don't commit them or treat `.agents/` as source.
- Scripts under `windows/`, `packaging/`, and `*.sh` at the repo root are user-facing deployment tooling with platform-specific behavior (VBS/CMD/PowerShell/launchd/Termux); changes there can't be verified by `cargo test`. Launchers track processes with PID files (`$OXIDESWARM_HOME/run`, default `~/.oxideswarm/run`) and never kill by name pattern; the launch flow (master `--listen 0.0.0.0:8088`, dashboard on loopback unless asked, worker `--master HOST:8088` with the copied secret) is the same in `switch_role.sh`, `windows/oxctl.ps1`, `connect_remote.*` and the installers. No script may hard-code `--simulate-gpu`, private LAN IPs, or hostnames.
- `.gitattributes` fixes line endings: `*.sh`/`*.py` are LF, `*.cmd`/`*.ps1`/`*.vbs` are CRLF (a CRLF `.sh` breaks under Git Bash, an LF `.cmd` can lose its labels). Shell scripts must stay bash-3.2 compatible (macOS `/bin/bash`): no `mapfile`, no associative arrays, guard empty arrays under `set -u`.
- **Test isolation**: a test (or script) must never read or write the developer's real `~/.oxideswarm` (it holds the real `cluster.secret`, `master_key.bin` and saved tickets). Give child processes a temp `HOME`/`USERPROFILE` with `Command::env`, never `std::env::set_var("HOME")`; `connect_remote.sh --dry-run` writes nothing. A master started with `--p2p` creates `master_key.bin` and `cluster.secret` under HOME unless the test passes `--ephemeral-key` / a temp key file / `--secret-file`.
- Multi-platform support is designed for and verified across diverse compute nodes (macOS Apple Silicon/Intel, Windows x86_64 with discrete GPUs, Linux servers, Android ARM64 devices).
