# Changelog

All notable changes to OxideSwarm are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- `scripts/ci_push_runs.py` prints each CI run for a push on `master` that is not green with its class (failing test, job never acquired, cancelled by an account, other) and whether the window has no run with a failing test; the `fuzz` job retries the nightly toolchain download; a rule that nobody cancels a run for a push on `master` (design 0088, `CI-1`).
- `submit --verify <N>` (with `--verify-file`) runs a task again on N other matching workers and compares the declared outputs by BLAKE3, printing `verified` or `mismatch` (exit 4); the MCP `submit` tool takes `verify` and `verify_file`. Client side only, no wire change (design 0089 D3, `VERIFY-1`).
- `scripts/agent_bridge.py claim` (create-only id claims on the hub for design numbers, Q ids, BACKLOG phases and item ids) and `activity --branch/--pr/--files/--files-from-git/--overlap` (changed files on the activity record and an overlap check), so parallel agents stop reusing ids and see who edits the same files (design 0087, `COORD-1`, `COORD-2`).

### Fixed
- A worker whose sandbox base became unusable (missing, not writable, not private) refuses the task with `Task rejected by worker: sandbox base unusable: ...`, which the master hands to another worker without charging a retry, instead of failing the task for good; no wire change (`BUG-25`, [design 0090](docs/design/0090-sandbox-base-refusal-hand-back.md)).
- The Android bridge tests wait until a stopped worker has finished draining (`common::stop_and_settle`) before the next test starts; the detached `STOPPED` write of the previous test could overwrite the `ERROR: Invalid cluster secret` status the next one had just caused (`TEST-48`).
- `test_sched2_max_queue_size_scheduler_policy_wire_codec_timeout_and_p2p_ticket` waits up to 30 s, by condition, for each of its two in-process masters to accept connections (was 50 tries 20 ms apart, one second) (`TEST-49`).
- The reaper boundary test (`TEST-42`) times everything from just before the Register is sent, so it fails only on a reaper that really fires before its timeout; a starved runner that reaches the 100 ms check after the timeout no longer fails it, and the reap is bounded at 5 s instead of 450 ms, with the time printed.
- The Agent Mesh hub no longer disconnects a sender as a "slow consumer" because of the hub's own replies: it now waits for room in the sender's outbound queue before it handles the next request, so a burst of requests to an unknown node id (one NACK each) slows the sender down instead of overflowing its queue of 8 to 1024 messages. This was the cause of the intermittent `test_slow_consumer_is_disconnected_instead_of_buffering_forever` failures on macOS CI (`TEST-27`).
- A worker whose master went away while it uploaded a finished task's output files no longer buffers the task as failed for the resume, and a sandbox lock file unlinked by a sweep can no longer be locked by a second opener (design 0091, `TEST-23`).
- The speed-aware batch test (`TEST-44`) asserts where design 0060 D2 places the tasks (no task reaches the slow worker before its wait cap plus its own run, with the slow worker now 10x slower instead of 5x so load cannot erase the difference) instead of a 1.5x ratio between two wall-clock times, which a loaded runner broke without any change in placement; the batch times are printed.

## [0.4.1] - 2026-11-17

A patch release with no wire change: it still speaks protocol 10 with the one-version window of `0.4.0`, uses the same master store format (4), and mixes freely with `0.4.0` (and, like `0.4.0`, serves `0.3.0` workers and clients). It fixes the two defects the Windows smoke test of `0.4.0` found (`BUG-23`, `BUG-24`) and makes four flaky tests deterministic or self-describing (`TEST-29`, `TEST-33`, `TEST-41`).

### Upgrading from 0.4.0

- Replace the binaries in any order; no clean stop is needed for this upgrade. On Windows, replace `windows\oxctl.ps1` (and the `.cmd` launchers) too: from `0.4.1` on, `oxctl.ps1 stop` stops the master with Ctrl+C, so a master with `--state-dir` compacts its journal before the next protocol upgrade (`BUG-23`).
- A master whose `--state-dir` is on exFAT or FAT32 now refuses to start, with a message that names the file system (`BUG-24`). Move the directory to an NTFS (or ReFS) drive first; with `0.4.0` such a master started once and then refused its own `members.json`.

### Changed
- CI: the `cargo test --workspace` step of `workspace tests` stops at 45 minutes, prints a heartbeat line with the last output line once a minute (`scripts/ci_heartbeat.py`), and an `if: always()` step prints the process tree, memory and the last 120 lines of the test output, so a hung or starved run names the running test instead of losing the runner without a log (`TEST-29`, Partial).

### Fixed
- `windows\oxctl.ps1 stop` (and `stop_worker.cmd`, `switch_role.cmd`, and `start_master.cmd` before a restart) first sends the tracked master or worker a console Ctrl+C, waits up to 15 s, and only then uses `taskkill /F /T`, so a master with `--state-dir` compacts its journal and the next protocol version accepts it; it prints which way each process stopped (`BUG-23`, [design 0086](docs/design/0086-graceful-windows-stop.md)).
- A master refuses a `--state-dir` on a volume that keeps no file permissions (exFAT, FAT32) at start-up, before it writes anything there, with a message that names the file system and asks for an NTFS directory. Before, it started once and then refused every restart because `members.json` looked readable by everyone, with an `icacls` hint that cannot work there. The same message replaces that hint for private files on such a volume. Windows only (`BUG-24`, [design 0085](docs/design/0085-state-dir-without-permissions.md)).
- The `rv158_probe_result_during_master_shutdown_is_lost_and_task_reruns` probe keeps the master and worker debug log in memory and prints it (the marker file, the task and worker id, every line that names them, every warning) when a round ran its task twice, and shows `evacuation=` beside `retry=` and `failover=`; `RV158_ROUNDS` and `RV158_ZERO` extend a local loop. One CI round ran the task twice with no retry or failover charged; it did not repeat in 6,884 local rounds, so the cause is not found yet (`TEST-41`, Partial).
- `test_stress_high_volume_worker_churn` waits up to 60 s for its 30 tasks (was 20 s) and 30 s for its workers (was 5 s), ending as soon as they are done, and a timeout now lists each task that did not complete with its state and counts (`TEST-33`, Partial: the CI failure was not reproduced).
- `test_stress_high_volume_worker_churn` keeps each retired worker (and so its sandbox base directory) alive until the end of the test; dropping it deleted the directory under a worker that could still be given a task, which then failed for good with "The sandbox base directory ... is not writable" (`TEST-33`).

## [0.4.0] - 2026-11-17

A minor release with one wire change under `0.x`: protocol version 10 adds an extension slot to tasks (`PROTO-3`) and, for the first time, a one-version compatibility window (`PROTO-4`), so a `0.4.0` master keeps serving `0.3.0` workers and clients while they are upgraded one at a time. It also adds `master --discovery-port` (`CLI-2`), a CI job that runs the newest release against each pull request (`PROTO-2`), the first fuzz targets (`LV-1`), and fixes for flaky tests (`TEST-27` to `TEST-40`).

### Upgrading from 0.3.0

- **Protocol version 10 with a one-version window (`PROTOCOL_VERSION_CURRENT = 10`, `PROTOCOL_VERSION_MIN_COMPATIBLE = 9`):** **upgrade and restart the master first**. A `0.4.0` master serves `0.3.0` workers and clients unchanged (`oxideswarm workers` tags them `proto:9`); a `0.4.0` worker or client is refused by a `0.3.0` master. The CI job `release skew (ubuntu-latest)` showed both results against the `v0.3.0` archives ([DEPLOYMENT.md](DEPLOYMENT.md) section 3.5, [design 0083](docs/design/0083-one-version-window.md)).
- **Master state store format 4:** with `--state-dir`, stop the `0.3.0` master cleanly (`SIGINT` or `SIGTERM`) before replacing the binary. Rolling the master back to `0.3.0` needs a copy of `--state-dir` made before the upgrade. On Windows, `windows/oxctl.ps1 stop` ends the master with `taskkill /F`, which skips that clean stop: start the `0.3.0` master in a console window on the same `--state-dir` and stop it with Ctrl+C before the upgrade (`BUG-23`).
- **Reserved tag prefixes `ext:` and `proto:`:** the master adds them; a worker-supplied `ext:` tag from a protocol 9 worker and every worker-supplied `proto:` tag are dropped ([design 0082](docs/design/0082-task-extension-slot.md)).

### Changed
- **Wire change: protocol 10** (`PROTOCOL_VERSION_CURRENT = 10`, `PROTO-3`, [design 0082](docs/design/0082-task-extension-slot.md)): `Task` and `TaskRequirements` end with a new `extensions` list. With the one-version window below, a protocol 10 master still accepts protocol 9 workers and clients (`0.3.0`), so **upgrade and restart the master first**, then workers and CLIs one at a time ([DEPLOYMENT.md](DEPLOYMENT.md) section 3.5); a protocol 10 worker or client is refused by a protocol 9 master. Rolling a master back needs a copy of its `--state-dir` made before the upgrade (store format 4). The master state store format advances from `3` to `4`: with `--state-dir`, stop the previous master cleanly (`SIGINT` or `SIGTERM`) first, so its journal is compacted and carries over at startup. By the release-train rule (design 0076 D1) a release follows within 48 hours.
- The error of a task whose declared output (`submit --output`, `Task::output_globs`) is missing now also lists what the top level of its sandbox holds (names and sizes, at most 20, no host path), for example `The sandbox root holds 2 entries: out.txt.tmp (5 B), sub/.`, so a missing file that was written under another name, in another directory, or taken away before collection can be told from a script that wrote nothing (`TEST-23`). The older `expected_outputs` path no longer reports a metadata error other than "not found" as `did not produce`: it says `could not examine '<file>': <error>` ([design 0013](docs/design/0013-task-output-validation-and-harvesting.md)).

### Added
- **A one-version compatibility window** (`PROTO-4`, [design 0083](docs/design/0083-one-version-window.md)): `PROTOCOL_VERSION_MIN_COMPATIBLE` is `CURRENT - 1` (9 at protocol 10). The master learns each peer's protocol version, encodes everything it sends in that version (the `RegisterAck` and every reply echo the peer's version, a protocol 9 worker receives its task without the extension lists, and an extension a worker must understand is never placed on it), and reads the protocol 9 `SubmitTask` layout. `oxideswarm workers` lists such a worker with the master-added tag `proto:9` (the eleventh reserved tag prefix), and the master logs a warning once per session. A worker or client takes from the master only an echo of its own version. A pull request that cannot be additive closes the window; the layout test enforces the rule and `crates/core/tests/data/wire_layout_previous.txt` (the layout file of `0.3.0`) is the oracle of the cross-version tests. The CI job `release skew` now derives the expected result of each pair from the two protocol constants and fails on a difference.
- The task extension slot (`PROTO-3`, [design 0082](docs/design/0082-task-extension-slot.md)): `Extension { id, critical, bytes }` in `Task::extensions` and `TaskRequirements::extensions`, a registry of ids (empty until the first feature that needs one), limits (16 per list, 64 KiB each, 256 KiB per task), and the rules for a receiver: an unknown non-critical extension is ignored and kept byte for byte, an unknown critical one is refused at submit and at assignment, and a task with a known critical worker extension is placed only on workers that advertise the `ext:<id>` tag (a tenth reserved tag prefix). There is no user-facing way to attach an extension yet.
- `fuzz/`: the first `cargo fuzz` (libFuzzer) targets for the parsers of untrusted bytes (`LV-1`): `inbound_frame` (frame reader, format dispatch and both decoders), `server_handshake` (cluster authentication v2 and v3, first frames) and `tree_manifest` (`TreeManifest::decode`), with seed corpora, `fuzz/regressions/` inputs and a `fuzz` CI job (60 s per target on pull requests, 10 minutes weekly). The crate is outside the workspace; a normal build does not change.
- `scripts/release_skew.py` and the CI job `release skew (ubuntu-latest)` run the newest release and the pull request's build in three loopback pairs and show a table of `works`, `refused with the version error` or `broken`; the job fails only on `broken` ([design 0076](docs/design/0076-protocol-compatibility-and-release-train.md) D2, `PROTO-2`).
- `scripts/agent_bridge.py activity` reports what a coding agent is doing now (`active`, `blocked`, `done`, `idle`, with task, step and note) to `nodes/<id>_activity.json`, separate from the machine heartbeat; `activity --show` lists every agent and marks one STALE after 20 minutes without an update while `active` or `blocked`, and `diagnose` and `peek` show the line ([design 0081](docs/design/0081-agent-activity-status.md)).
- `oxideswarm master --discovery-port <PORT>` (`RUSTY_GRID_DISCOVERY_PORT`, `[master].discovery_port`) moves the UDP discovery beacon off `8089`, and `0` turns it off, so two masters can share a machine (`CLI-2`, design 0084). A worker or client finds a moved beacon with `--master auto:<PORT>`; the default stays `8089`.

### Fixed
- Two Agent Mesh tests no longer race a fixed sleep (`TEST-39`, `TEST-40`): `test_sec6_real_cli_no_shell_flag_execution` waits until the spawned `--no-shell` node is registered, and `test_adv_large_payload_boundaries` and the burst counts of three test files wait (bounded) for the expected number of payloads.
- Agent Mesh simulation Suite 2 no longer fails when the hub delivers a payload later than a fixed sleep (`TEST-34`): `tests/test_agent_mesh_data_loss.py` waits (bounded) for the expected number of payloads instead of sleeping 0.05 to 0.3 s, still asserting exact counts and bytes; `tests/run_mesh_simulation_tests.py` prints the type, message and traceback of a failing suite, and the `switch_role` launcher test prints the launcher's output and logs on failure (`TEST-35`, cause not reproduced yet).
- Three timing-sensitive tests no longer depend on a wall-clock window that a starved CPU misses (`TEST-36`, `TEST-37`, `TEST-38`): the symlink-chain manifest test bounds validation at 10 s instead of 50 ms, the port-file reader test waits for 50 successful reads instead of 100 ms, and the re-dispatched task id test waits for the result by condition instead of for 800 ms.
- Two flaky unit tests made deterministic (TEST-28, TEST-31): `test_concurrent_submissions_share_group_commit_and_recover_across_restart` no longer asserts a 2 s wall-clock bound (group commit is proven by the fsync counter), and the detached-grandchild Blender probe test now waits for a ready marker written after `setsid` before the direct child exits.
- `tests/test_agent_bridge.py` no longer depends on the host's open ports (`TEST-30`): `agent_bridge.py` reads `OXIDESWARM_BRIDGE_ASSUME_LISTENING` (test seam, unset for real users) instead of probing 8088/8080, so a real master no longer fakes a split brain; the `mesh_auth` slow-consumer test (`TEST-27`) now checks the healthy node over its own connection, not behind the flooder's backlog, and prints the latencies.

## [0.3.0] - 2026-11-16

A minor release with breaking changes under `0.x`: protocol version 9 (task VRAM accounting, `FEAT-9a`), no auto-loading of working-directory config files (`SEC-10`), and removal of the dashboard chat route (`SEC-14`). It also adds the external read-only runtime directory allowlist (`FEAT-3e`), scheduler scale-out (`SCALE-2`) and several fixes.

### Upgrading from 0.2.0

- **Protocol version 9 (`PROTOCOL_VERSION_CURRENT = 9`, `PROTOCOL_VERSION_MIN_COMPATIBLE = 9`):** every master, worker and client must run `0.3.0`; protocol 8 peers are refused. **Upgrade and restart the master first**, then workers and CLIs ([DEPLOYMENT.md](DEPLOYMENT.md) section 3.5; `FEAT-9a`, [design 0068](docs/design/0068-task-vram-accounting.md)). The master state store format advances from `2` to `3`: with `--state-dir`, stop the `0.2.x` master cleanly (`SIGINT` or `SIGTERM`) first, so its journal is compacted and carries over at startup (design 0068).
- **`./rusty-grid.toml` and `./rusty-grid.json` are no longer auto-loaded** by any CLI command: pass `--config <PATH>` or set `RUSTY_GRID_CONFIG`, or move the file to `~/.oxideswarm/rusty-grid.toml`. The CLI prints a one-line notice to `stderr` when it skips a working-directory file (`SEC-10`, [design 0070](docs/design/0070-no-working-directory-config.md)).
- **`POST /api/chat` and the dashboard chat UI are removed** (`SEC-14`, [design 0071](docs/design/0071-remove-dashboard-chat.md)).
- **Windows relative task executables:** a relative staged executable path such as `./prog.exe` now resolves against the task's working directory inside the sandbox, and paths that escape the sandbox are refused (`BUG-21`, [design 0077](docs/design/0077-windows-relative-task-executables.md)).
- **Windows isolation without a fallback:** an elevated Windows worker under `--isolation fs|fs+net` no longer starts a task with its own elevated token when the restricted (LUA) token is missing or `CreateProcessAsUserW` fails; the task fails with the Win32 error. Run isolated Windows workers non-elevated, or expect such refusals (`SEC-11`, [design 0078](docs/design/0078-no-elevated-token-fallback.md)).
- **macOS isolation is narrower:** under `--isolation fs|fs+net` every Mach/XPC service lookup is denied except `com.apple.MTLCompilerService`, launchd job creation is denied, and user names resolve to numeric uids inside the sandbox (`whoami` and `id -un` print the uid) (`SEC-12`, [design 0033](docs/design/0033-os-level-task-isolation.md)).
- **Agent Mesh launchers (`SEC-15`, [design 0079](docs/design/0079-agent-mesh-launchers-safe-by-default.md)):** `run_agent_node.ps1` gains `-NoShell` and honours `OXIDE_MESH_NO_SHELL=1`; `run_agent_node_adb.sh` passes the hub token on standard input instead of the `adb shell` command line; nodes log a warning when a token is sent over `ws://` to a non-loopback host.
- **CI size check (`MAINT-1`, [design 0080](docs/design/0080-source-file-size-check.md)):** CI fails when a Rust file's production part (lines before its first `#[cfg(test)]`) exceeds 3,000 lines, except the files in `scripts/rust-file-size-allowlist.txt`.

### Security
- The macOS isolation profile (`--isolation fs|fs+net`) now denies every Mach/XPC service lookup and launchd job creation by default, with one allowed service, `com.apple.MTLCompilerService`, which Metal GPU tasks need to compile shaders (`cargo`, `rustc`, `git`, `cc` and `ld` need none), and new tests show that `launchctl submit`, `open -a`, `osascript` and a hard link to a secret have no effect outside the sandbox (`SEC-12`, [design 0033](docs/design/0033-os-level-task-isolation.md), `crates/worker/src/isolation.rs`). User names resolve to numeric uids inside a macOS-isolated task.
- Working-directory `./rusty-grid.toml` and `./rusty-grid.json` files are no longer auto-loaded by any CLI command (`worker`, `submit`, `status`, `master`, `doctor`, `ox-mode`, etc.), matching `oxideswarm mcp` (`SEC-10`, [design 0070](docs/design/0070-no-working-directory-config.md)): when a working-directory config file is present and neither `--config <PATH>` nor `RUSTY_GRID_CONFIG` is set, the CLI skips it, prints a one-line notice to `stderr`, and falls back to `~/.oxideswarm/rusty-grid.toml` (upgrade note: users or scripts that relied on auto-loading `./rusty-grid.toml` or `./rusty-grid.json` from the current directory must now pass `--config <PATH>` or set `RUSTY_GRID_CONFIG`).
- An elevated Windows worker no longer falls back to `CreateProcessW` with its own elevated token when the restricted (LUA) token is missing or `CreateProcessAsUserW` fails under `--isolation fs|fs+net`: the task fails with the Win32 error and the reason is logged once (`SEC-11`, [design 0078](docs/design/0078-no-elevated-token-fallback.md)).
- Agent Mesh launchers are safer by default (`SEC-15`, [design 0079](docs/design/0079-agent-mesh-launchers-safe-by-default.md)): `run_agent_node.ps1` gains `-NoShell` and honours `OXIDE_MESH_NO_SHELL=1` like the other launchers, `run_agent_node_adb.sh` passes the hub token to the phone on standard input instead of the `adb shell` command line, and the Rust node and `scripts/agent_node.py` log a warning (never the token) when a token is sent over `ws://` to a host that is not on loopback.

### Added
- Source file size check (`MAINT-1` step 3, [design 0080](docs/design/0080-source-file-size-check.md)): `ox-mode test size` (also part 3 of `ox-mode test lint`, and a step of the Linux `clippy` CI job) fails when a Rust file's production part (lines before its first `#[cfg(test)]`) exceeds 3,000 lines, except the files in `scripts/rust-file-size-allowlist.txt` (`crates/worker/src/isolation.rs`, `crates/cli/src/mcp.rs`, `crates/cli/src/mode_cli.rs`), whose maximum may only shrink (`crates/cli/src/size_check.rs`).
- Opt-in external read-only runtime directory allowlist for isolated workers (`--isolation-read-dir <DIR>` / `--allow-read-dir <DIR>`, `RUSTY_GRID_ISOLATION_READ_DIRS`, `[worker].isolation_read_dirs`, `HostDirs::extra_read_only_dirs`, `WorkerConfig::isolation_read_dirs`) across macOS Seatbelt, Linux Landlock, and Windows AppContainer (`FEAT-3e` / `R20`, [design 0074](docs/design/0074-external-runtime-allowlist-and-gpu-workloads.md)) plus GPU workload runbook ([docs/guides/gpu-workloads.md](docs/guides/gpu-workloads.md)) and `README.md` status/flag documentation.
- Task VRAM requirements and scheduler VRAM accounting (`FEAT-9a` / `Q56`, [design 0068](docs/design/0068-task-vram-accounting.md)): optional `TaskRequirements::vram_mb: Option<u64>` (`crates/core/src/task.rs`, `capabilities.rs`), CLI `oxideswarm submit --vram-mb <MB>` (alias `--vram`, implying `--gpu` when non-zero) with preflight connected-GPU VRAM warning (`crates/cli/src/cli_app.rs`), MCP `submit` `vram_mb` parameter plus `status`/`workers` `vram_mb` reporting (`crates/cli/src/mcp.rs`), Web UI `POST /api/tasks` `vram_mb` field (`crates/master/src/web_ui.rs`), `AssignedLoad::vram_mb` tracking across `Scheduled`, `Running`, and adoptable-hold tasks (`crates/master/src/queue.rs`), static `WorkerIndex` / scheduler VRAM filtering (`statically_fits_caps`, `statically_fits`), dynamic per-pass and cross-pass `Seat::used_vram_mb` capacity enforcement + `hold_back` anti-starvation (`crates/master/src/scheduler.rs`), `PROTOCOL_VERSION_CURRENT` bumped `8` -> `9` with `LegacyV6ToV8BinaryClientMessage` explicit version errors (`crates/core/src/protocol.rs`), and `STORE_FORMAT_VERSION` bumped `2` -> `3` (`crates/master/src/store.rs`).
- Scheduler and queue scale-out (`SCALE-2`, [design 0050](docs/design/0050-scale-out-architecture.md)): `WorkerIndex` / `RegisteredIndex` bitset matching across placement attributes, protocol capabilities (including `WORKSPACES` and `TREE_V2`), free slots, and mobile thermal/battery buckets (`crates/master/src/worker_index.rs`); `SCAN_PAGE = 512`, `DEFAULT_MASTER_MAX_BATCH_SIZE = 1024` (`master --max-batch-size`, `RUSTY_GRID_MAX_BATCH_SIZE`, `[master].max_batch_size`), adaptive micro-batch debounce, and up to 16-batch drain (`crates/master/src/{scheduler,server}.rs`, `crates/cli/src/{cli_app,config}.rs`); weighted round-robin per-submitter `FairShareQueues` tagged per client connection (`crates/master/src/fair_share.rs`, `queue.rs`); `receiver_count() > 0` fast-path guards on dashboard broadcasts; single-flight batched `ColdResultStore` spill of terminal `TaskResult` payloads under `<state_dir>/cold_results/<xx>/<task_id>.bin` (`OXSWCLD1`, `DEFAULT_MAX_HOT_TERMINAL_TASKS = 1024`, replay file reuse) with RAM-only `GetTaskStatus` (`crates/master/src/{cold_results,queue,store}.rs`); and post-`SCALE-2` 3-run `500w` / `1000w` benchmark records (`benchmarks/grid/results/2026-11-15-scale2-windows-amd64-{500w,1000w}.json`).

### Removed
- Master dashboard `POST /api/chat` route, `run_agy` child-process launcher, and dashboard chat UI (`SEC-14`, [design 0071](docs/design/0071-remove-dashboard-chat.md)).

### Fixed
- Windows tasks now resolve relative staged executable paths (`./prog.exe`, `.\prog.exe`, `sub/prog.exe`, `sub\prog.exe`, including under `--cwd`) against the task's working directory inside the sandbox across `--isolation off`, `fs`, and `fs+net`, refuse sandbox escapes (`..\prog.exe`, junctions targeting outside the sandbox, drive/root-relative prefixes), keep `.com`/`.exe`/`.bat`/`.cmd` and `MZ` validation, wrap `.bat`/`.cmd` via `cmd.exe /d /s /c`, and pass an absolute `lpApplicationName` to `CreateProcessW` / `CreateProcessAsUserW` (`BUG-21`, [design 0077](docs/design/0077-windows-relative-task-executables.md), `crates/core/src/capabilities.rs`, `crates/worker/src/{isolation,runner/supervise}.rs`).
- Bounded 2-lane QUIC worker session data-lane backlog in `router_task` at `MAX_PENDING_DATA_MESSAGES = 256` and `MAX_PENDING_DATA_BYTES = 64 MiB` so `outbound_tx` backpressures senders when a worker stops draining its data stream, and added a `DATA_LANE_WRITE_TIMEOUT = 60 s` per-write timeout on `data_writer_task` that disconnects stalled sessions and fails over their tasks (`BUG-19`, [design 0069](docs/design/0069-bounded-quic-data-lane.md), `crates/master/src/{session,server}.rs`).
- `WorkloadScheduler::dispatch` (`crates/master/src/scheduler.rs`) now attempts a non-blocking `sender.try_reserve()` first and defers full-channel deliveries to bounded per-assignment waiters (`DISPATCH_RESERVE_TIMEOUT = 5 s`, capped at `MAX_IN_FLIGHT_DISPATCH_WAITERS_PER_WORKER = 16` per worker) that requeue timed-out assignments uncharged via `TaskQueue::requeue_dispatch_failure`, preventing one slow worker from stalling the rest of a scheduling pass (`BUG-20`, [design 0075](docs/design/0075-non-blocking-dispatch.md)).
- Help and tool texts that described an older state: `worker --isolation` no longer says isolation is macOS only (macOS, Linux and Windows are supported; `crates/cli/src/cli_app.rs`), and the MCP `doctor` tool names checks C1 to C8 (`crates/cli/src/mcp.rs`). Documentation statuses were corrected in the same change (`DOC-9`, `docs/BACKLOG.md`).
- Android bridge non-blocking stop, start race guard, poison-tolerant locking, and `aarch64-linux-android` CI target check (`AND-5`, [design 0073](docs/design/0073-android-bridge-nonblocking-stop.md)): `stop_worker_impl` now signals shutdown, sets status `STOPPING`, and joins the worker thread on a background thread before setting `STOPPED` so `nativeStopWorker` does not block the Android UI thread; `start_worker_impl` claims `running` atomically with `compare_exchange` and refuses starts while a previous worker is still draining; mutex accesses in `crates/android_bridge/src/lib.rs` use `unwrap_or_else(|e| e.into_inner())`; and `.github/workflows/ci.yml` runs `cargo check -p rusty_grid_android_bridge --target aarch64-linux-android --locked` on `ubuntu-latest`.

### Security

(`PROTOCOL_VERSION_CURRENT` in `crates/core/src/protocol.rs`), and the oldest version a peer accepts

2. Replace and restart the workers. The upgraded master refuses a worker that still runs an

3. Replace the binary that clients, scripts and `oxideswarm mcp` use.

The order and the reasons are in [DEPLOYMENT.md](DEPLOYMENT.md) section 3.5.

- Tool probes and Cargo builds: workers advertise `tool:cargo`, `tool:rustc` and `tool:git`, `submit --require-tool` and the MCP `tools` field pin a task with `require:tool=`, and a compile task with a `Cargo.toml` runs `cargo build --offline` (`submit --type compile --source`, MCP `type: "compile"`) ([design 0039](docs/design/0039-agent-workspaces.md) D8, [design 0020](docs/design/0020-bounded-host-capability-probes.md)).
- Several blob uploads in flight from one client, and up to 16 blob requests handled at once per client connection on the master ([design 0006](docs/design/0006-content-addressed-data-plane.md), [design 0039](docs/design/0039-agent-workspaces.md) W9).
- `oxideswarm doctor` shows whether each worker link is direct or relayed (`LINK` column, check C7) and measures blob throughput to each worker (check C8, `--skip-throughput`) ([design 0001](docs/design/0001-two-node-readiness.md)).
- `oxideswarm secret join-token` and `oxideswarm join`: one token, read from standard input, carries the master's address or ticket and the cluster secret, writes the secret at mode 600 and runs the `doctor` checks ([design 0048](docs/design/0048-join-token.md)).
- Release workflow `.github/workflows/release.yml`: archives for Linux, macOS and Windows, with and without `gpu-wgpu`, plus `SHA256SUMS`, built on a `v*` tag, and an install section in `README.md`.
- `--relay-url <URL>` (`RUSTY_GRID_RELAY_URL`, `relay_url`) for the master, workers and clients, so P2P traffic can use your own iroh relay instead of the public n0 relays, and a [self-hosted relay guide](docs/guides/self-hosted-relay.md) ([design 0049](docs/design/0049-custom-relay.md)).
- Guide [Offload cargo test to another machine](docs/guides/offload-cargo-test.md), from the command line and over MCP.
- Benchmarks `benchmarks/grid/bench_grid.py` for task overhead, repeated uploads and the offload of `cargo test` to a workspace on another machine (`--only c`), each with a dated record ([benchmarks/grid/README.md](benchmarks/grid/README.md)).

### Changed
- Removed `oxideswarm mcp --sse` in favour of stdio-only MCP transport and fail-closed client secret enforcement on non-loopback masters ([design 0004](docs/design/0004-mcp-and-discovery.md)).
- Enforced bounded host capability probes, active queue budgets, oversized task result handling, and inbound JSON/blob request routing ([design 0008](docs/design/0008-oversized-task-results-and-active-queue-budget.md), [design 0018](docs/design/0018-inbound-json-blob-request-routing.md), [design 0020](docs/design/0020-bounded-host-capability-probes.md)).
- Protocol version 7. Version 4 removed `compute_intensity` from the GPU task spec and added `ResumeSession`, version 6 added the `Hello` probe and `Task::workspace`, and version 7 added `ListWorkspaces` / `WorkspacesList`. Older peers are refused ([design 0040](docs/design/0040-protocol-versioning.md), [design 0039](docs/design/0039-agent-workspaces.md)).
- For client commands (`submit`, `status`, `doctor`, `cancel`, `result`, `workspaces`, `mapreduce`, and `join`), `OXIDESWARM_P2P_TICKET` and `OXIDESWARM_MASTER` now outrank the legacy `RUSTY_GRID_MASTER_ADDR` environment variable ([design 0039](docs/design/0039-agent-workspaces.md) D7).
- `gen3d` and `autorig` build only with the opt-in Cargo feature `3d`; a worker without it does not take 3D tasks. Dead code, the Android lease shims and the second connection loop of the master were removed, and leftover task sandboxes are swept at worker start-up ([design 0044](docs/design/0044-dead-code-and-connection-loop-unification.md)).

### Security
- Private files on Windows (the cluster secret and similar) get an owner-only DACL, as mode 600 does on Unix ([design 0047](docs/design/0047-windows-private-files.md)).
- After a worker is killed with `kill -9`, a supervisor per task group ends the task's processes within 5 s on Linux and macOS ([design 0031](docs/design/0031-containment-after-worker-crash.md)).
- Agent Mesh refuses binary inputs that are neither base64 nor hex, and no longer reads a hub-local file named by a peer.

### Baseline

What the workspace already held before this changelog was kept:

- Six-crate Rust workspace (`rusty_grid_core`, `rusty_grid_master`, `rusty_grid_worker`, `rusty_grid_cli`, `rusty_grid_android_bridge` (`oxideworker` library), `agent_mesh`).
- Master task scheduler, worker capability matching, failover sweeps, UDP LAN discovery (`8089/udp`), and iroh QUIC P2P transport (`--p2p`).
